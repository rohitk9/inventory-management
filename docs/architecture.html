Architecture Overview

Factory Inventory Management System

A full-stack demo application for inventory tracking, order management, demand forecasting, and spending analytics across factory warehouses. Vue 3 frontend, FastAPI backend, no database — all data is served from in-memory JSON fixtures.

1Tech Stack

Frontend

Vue 3 + Vite

Composition API, Vue Router, Axios. SVG charts and CSS Grid layouts, no charting library.

localhost:3000
Backend

Python FastAPI

Pydantic models validate every response. Uvicorn as the ASGI server, CORS open for local dev.

localhost:8001
Data

In-memory JSON

No database. server/data/*.json is loaded once at startup and filtered in Python on every request.

server/mock_data.py

2System Architecture

Request/response cycle: the SPA calls api.js → FastAPI route → in-memory filter functions read from data loaded once at process start → Pydantic serializes the response → Vue re-renders computed properties.

3Request Data Flow

STEP 1

User changes a filter

Warehouse, Category, Order Status, or Time Period updates shared state in useFilters.js.

STEP 2

View calls api.js

The active view builds a query string and calls the matching api.js method with Axios.

STEP 3

FastAPI route handles it

The route in main.py reads query params and calls apply_filters() / filter_by_month().

STEP 4

Filter over in-memory lists

Filtering runs in plain Python over lists loaded once from server/data/*.json — no query engine, no persistence.

STEP 5

Pydantic validates response

Results are coerced into typed models (InventoryItem, Order, etc.) before serialization.

STEP 6

View updates computed data

Raw response lands in a ref; derived values (totals, chart data) recompute automatically.

4Filter System

Four filters apply across nearly every page, held as shared singleton state so every view stays in sync without prop drilling.

7Notes for Contributors

No persistence layer. All data lives in Python lists loaded once at startup from server/data/*.json. Restarting the backend resets everything.
Auth is mocked. useAuth.js hardcodes the current user; there is no real login, token, or session anywhere in the stack.
api.js has methods with no backing routes. getTasks, createTask, and the purchase-order write methods call endpoints that don't exist in main.py — only GET /api/backlog reads purchase_orders data server-side.
